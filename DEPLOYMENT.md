# Deployment Guide (preview, not production approval)

The code works locally and includes deployment scaffolding. **No hosting account was accessed and no public deployment has been performed.**

## 1. Verify locally

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m uvicorn dispatchforge_app.web:app --reload
```

Open `http://127.0.0.1:8000/demo`. The app creates an ignored local SQLite database.

## 2. Publish the repository to GitHub

Follow the separate `10-COMMITS.md` provided with the milestone bundle if you want exactly 10 feature commits, or commit the updated project files normally. Confirm no `.env`, database, or credential files are staged.

## 3. Choose managed hosting + persistent PostgreSQL

The included `render.yaml` is an example starting point. Create a persistent PostgreSQL database and obtain its private connection URL from your provider. **Free web service disks may be ephemeral**; do not rely on local SQLite files in hosted production mode.

Provision the web service with:

```text
APP_ENV=production
APP_SECRET=<32+ character unpredictable secret, generated by your hosting provider>
DATABASE_URL=postgresql+psycopg://<username>:<password>@<host>:5432/<database>
```

Do not paste actual secrets into GitHub, README files, screenshots or chat. Do not literally use the `<...>` placeholders above.

Build:

```bash
python -m pip install -r requirements.txt
```

Start:

```bash
uvicorn dispatchforge_app.web:app --host 0.0.0.0 --port "$PORT"
```

Health check: `/api/health`. If using Render, consult its current documentation for plan availability and pricing. The example uses a paid web-service class because the product ultimately needs reliable hosting; you may adapt this for a nonproduction preview.

## 4. What we still must do before inviting businesses

- Versioned migrations instead of automatic `create_all` schema setup.
- Email verification, recovery and proper team invitation.
- Account rate limiting and security review.
- Managed backup/restore processes and observability.
- Customer-facing policies, consent and operational support.
- Concurrency/load testing against the hosted PostgreSQL database.

A public *demo* can be hosted earlier with clear disclaimers and **only fictional data**. A real warehouse should not adopt it as its system of record yet.

## 5. Domain and mobile future

Once hosted, connect your purchased domain using your hosting provider's DNS instructions. Keep the API backend separate from the HTML/JS client so a future mobile app can use the same authorized endpoints.
